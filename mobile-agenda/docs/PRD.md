## 1. 时间轴视图（核心改版）

### 1.1 用户没说出口但真实需要的需求
1. **一眼看出"现在几点、现在该干嘛"**：左侧小时刻度（0–24 或 12a–12p），当前时刻一条红线 + 左侧 HH:MM 标签，每 30 秒自动刷新位置；打开日视图自动滚动到"当前时间前 1 小时"处，而不是永远停在 0 点。
2. **当前时段高亮**：正在进行的事件块加高亮描边/加粗，已结束的事件灰显；不标"已完成"（大学生日程不是待办，别做成打卡）。
3. **空档可点**：点击时间轴空白处（某小时格内）→ 半屏新建卡，开始时间自动预填点击位置对应时刻，结束时间预填 +1 小时；事件块点击 → 详情卡（查看、改提醒、编辑、删除）。
4. **跨天/全天事件单独摆**：时间轴上方固定一条"全天/跨天"横条区（Chip 样式横排），**不进 24h 轴**——否则跨天事件画不满一屏还误导。跨天事件在各天视图的全天条都出现，标注"第 x/y 天"。
5. **周视图在窄屏的取舍**：手机上 7 列真实网格每列仅 ~50dp，文字必然不可读。采用 Google Calendar 的做法但降级信息密度：7 列网格，块内只画**颜色块 + 课程/事件名前 3 字**，列头"一 7"式日期；点列头切到那天日视图，点块看详情。同时提供更实用的"周列表"开关（默认周网格）：7 天纵向分区，每天一个迷你时间轴摘要。两者共用数据，不另做逻辑。
6. **12h/24h 制**：右上角菜单切换，影响所有时刻显示（轴刻度 12a/6a/12p/6p），存储用 24h 不变。
7. **教学周标尺**（与课表联动）：配置了学期起始日后，日/周视图标题下显示"第 3 周 · 周三"，让课表周次可感知。

### 1.2 事件重叠与布局规则
- 重叠事件贪心分列：同一时段最多并排 3 列，第 4 个起叠层（右侧压 1/3 显示），块上文字只保标题。
- 默认事件时长：解析结果无 end 时按 1 小时落位（仅展示用，不改存储）。

### 1.3 边界情况清单
- 0–8 点无任何事件：打开时自动滚动到当前时刻，而非 0 点空屏。
- 深夜 0–6 点查看"今天"：若当前在 0 点后且今天无日程、昨天有跨天事件，全天条正常显示。
- 时间轴一格内挤 3+ 个事件：叠层策略 + 详情卡兜底，不做智能缩放。
- 事件恰在 23:30–00:30 跨过午夜：按跨天事件处理（进全天条，标"跨午夜"）。
- 手动改了系统时间/时区：红线按系统时间走，不做时区处理。
- 周视图某天事件 20+ 条：块只画时长比例，溢出折叠"+n"。
- 空日程日：轴上不画"空空如也"大空态，保持完整时间轴 + 底部提示"今天没有安排，点空档或说话键添加"。

### 1.4 验收标准（简式）
- G 日视图打开 / W 无操作 / T 视口定位到当前时间前 1 小时，红线显示且 HH:MM 与系统时间一致；静置 1 分钟红线位置更新。
- G 现在有进行中的事件 / W 看 / T 该块有高亮描边，过去块灰显。
- G 点击 14:00–15:00 空档 / W 弹出新建卡 / T 开始时间预填为点击时刻（12h 制下显示 02:00 PM）。
- G 存在"周一 20:00 至周二 08:00"事件 / W 看周一视图 / T 事件出现在顶部全天条且不在轴内。
- G 切到周视图 / W 看 / T 7 列列头含星期与日期，今天列头高亮；点任一列头跳到该天日视图。

## 2. 语音与快速记录

### 2.1 用户没说出口但真实需要的需求
1. **失败不能是死胡同**。用户已遇到"此手机没有可用的语音识别服务"这个一次性报错——那是终点，不是入口。必须建成三级链路（见 §6 决策树），任何一级失败自动降级，**用户永远有一条能录进去的路**（最差也是打字，而打字时提示用户"输入法自带语音键也能说"）。
2. **说完即所得**：识别完成直接进入解析，结果直接弹确认卡，中间不需要任何按钮点击。
3. **确认卡是编辑器不是展览品**：解析结果每条可改标题/时间/地点，可单条删除；保存后 toast 带 5 秒"撤销"。
4. **录音状态可见**：说话键三态——待命（静态麦）、录音中（键体放大+呼吸动画+"● 正在听…"）、处理中（转圈+"识别中…"）。状态文案显示在键上方 24dp 处，不打断视线。
5. **识别记忆**：某 ROM 的系统识别一旦连续失败 2 次，本次安装内记住"该机不可用"，之后点击说话键直接走云端转写，不再让用户重复踩坑。

### 2.2 边界情况清单
- 麦克风权限被永久拒绝：说话键点击 → 直接弹半屏文字输入（预置提示"麦克风权限未开，可直接打字，或用输入法的语音键"），不弹系统设置跳转骚扰。
- 说话中途来电/切后台：识别取消，无残留状态。
- 云端转写超 60 秒未返回：超时提示 + 自动落入文字兜底。
- 录音文件无声音（权限被系统静默禁用）：转写结果为空 → 提示"没录到声音，试试再按一次或直接打字"。
- 识别出的文字解析出 0 条日程：确认区显示"没听出时间，试试：明天晚上8点和小王吃饭"，文字保留可改。
- 转写模型未配置：语音决策树里跳过该级，文案明确"可在设置中配置转写模型启用云端识别"。
- 连续说话追加：识别结果追加到当前输入框内容后（保留现有行为）。

### 2.3 验收标准
- G 系统识别可用 / W 点说话键说完 / T 无需其他点击，确认卡自动弹出且条数≥1。
- G isRecognitionAvailable=false 或连续 2 次系统识别失败 / W 再点说话键 / T 自动进入云端录音态（若已配转写模型），按钮变录音中。
- G 云端转写也未配置 / W 点说话键 / T 直接弹文字输入并提示可用输入法语音键，**不出现任何含"没有可用的语音识别服务"字样的死文案**。
- G 保存 3 条日程 / W 点撤销 / T 3 条被删除，闹钟同步取消。

## 3. 课程表导入（入口：右上角 ⋮ 图标菜单 → 📥）

### 3.1 用户没说出口但真实需要的需求
1. **学期起始日是整条链路的锚**：课表写"第 3 周周一"，不知道"第一周周一是几号"就换算不出任何日期。导入流程第 1 步必须让用户确认"第一教学周的周一"（默认按当前日期所在周智能猜测，可改），之后所有周次才有意义。
2. **必须有人工确认关，AI 直接入库必出事**：视觉识别错一个"周三"用户整学期迟到。导入后进预览页：逐条可编辑/删除、显示换算后的**首次上课具体日期**（如"首课 9 月 14 日（周一）08:00"）、与已有日程时间冲突的标黄提示，确认后才写入。
3. **重导=替换**：二次导入时先清掉所有 `source:"timetable"` 的旧事件再写入新表（确认页明示"将替换现有课表事件 n 条"），避免叠加双份。
4. **第几节 → 几点** 的换算表可改：截图里没有作息时刻表时，用内置默认大学时刻表（见 §4 契约），预览页可编辑任意一节的起止时间，改完全部课程即时重算。
5. **截图失败的降级要具体**：见 §4.3。

### 3.2 流程
`⋮ → 📥 → ① 选/拍截图（或直接粘贴文字课表）→ ② 调视觉模型解析 → ③ 确认学期起始日与作息时刻 → ④ 预览（可编辑/删/冲突提示）→ ⑤ 写入并提醒已设`

### 3.3 边界情况清单
- 所配模型不支持图像（API 报错或内容为空）：明确提示"当前模型不支持看图，请在设置→视觉模型中配置（如 glm-4v / qwen-vl 等）"，不静默失败。
- 截图模糊/竖排/手写：解析出 courses 为空或 <2 条 → 提示"没认出课程，试试更清晰的截图，或切换到文字粘贴"。
- 同名课程多条（如高数 1-8 周和 9-16 周地点不同）：按两条独立课程保留，不合并。
- 课表含周六日课：正常支持，dayOfWeek=6/7。
- 总周数超过截图标注（如 20 周）：以截图为准写入 term.totalWeeks。
- 学期起始日选错后续发现：设置页可改"学期起始日"，改后提示"重导课表或手动调整已生成日程，本次不自动改动已有事件"（不静默重排）。
- 导入的课程撞上用户手写的日程：预览页冲突标黄，用户自行取舍。

### 3.4 验收标准
- G 传入清晰课表截图 / W 解析完成 / T 预览页条数与截图课程数一致，每条含节次→具体时刻（如"第3-4节 10:00–11:40"）与首课日期。
- G weeks=[1,16]、weekParity="odd" / W 换算 / T 仅第 1、3、5…15 周生成实例，共 8 条。
- G 已存在 20 条课表事件 / W 再次导入并确认 / T 旧 20 条被替换为新表，用户手写事件原样保留。
- G 模型返回非法 JSON / W 降级 / T 自动带错误信息重试 1 次，仍失败则展示可编辑文本兜底，全程无崩溃。

## 4. 【课程表导入契约】—— AI 视觉模型输出规范（开发直接实现）

**调用**：`POST {baseUrl}/chat/completions`，model=设置中的视觉模型。System prompt 要点：告知**今天的日期与星期**；要求只输出一个 JSON 对象，禁止代码块标记；周次区间拆分规则；"第3-4节"拆为 periodStart/periodEnd；单双周用 weekParity。用户消息 = 图片 + 文字课表（若用户粘贴了文字）。

**输出 JSON Schema**（字段名固定，缺省字段按默认值处理）：

```json
{
  "term": {
    "startDate": "2026-09-07",     // 第一教学周的周一，YYYY-MM-DD。截图有则取，无则由 app 让用户确认
    "totalWeeks": 16
  },
  "timeSlots": [                    // 第 n 节的起止时刻，升序；截图未给则 AI 按 JSON 默认模板输出
    { "period": 1, "start": "08:00", "end": "08:45" },
    { "period": 2, "start": "08:55", "end": "09:40" },
    { "period": 3, "start": "10:00", "end": "10:45" },
    { "period": 4, "start": "10:55", "end": "11:40" },
    { "period": 5, "start": "14:00", "end": "14:45" },
    { "period": 6, "start": "14:55", "end": "15:40" },
    { "period": 7, "start": "16:00", "end": "16:45" },
    { "period": 8, "start": "16:55", "end": "17:40" },
    { "period": 9, "start": "19:00", "end": "19:45" },
    { "period": 10, "start": "19:55", "end": "20:40" }
  ],
  "courses": [
    {
      "name": "高等数学B(上)",       // 必填，≤30字
      "teacher": "张三",             // 可空字符串
      "location": "教一 201",        // 可空
      "dayOfWeek": 1,               // 必填 1-7，1=周一（AI 负责归一化"周一/周1/Mon"）
      "periodStart": 3,             // 必填 起始节次
      "periodEnd": 4,               // 结束节次；单节课 = periodStart
      "weeks": [1, 16],             // 必填 [起始周, 结束周] 闭区间
      "weekParity": "all",          // "all" | "odd"单周 | "even"双周
      "notes": ""                   // 可空，如"1-8周 上机"
    }
  ]
}
```

**校验规则**（app 侧逐条校验，不合格的该条丢弃并计入提示）：
- dayOfWeek∈[1,7]；periodEnd≥periodStart≥1；weeks 为升序二元组且落在 [1, totalWeeks]；weekParity 缺省按 "all"。
- **不连续周次（如第 1–8 周和第 12–16 周）→ AI 必须拆成两条 course**，各自给 weeks 区间；app 不支持更复杂的周表示。
- timeSlots 覆盖用到的最大节次；缺的节次用内置默认模板补齐并在确认页标出。

**换算规则（app 侧，确定性代码，不经 AI）**：
- 上课日期 = term.startDate + (week−1)×7 + (dayOfWeek−1) 天。
- start = timeSlots[periodStart].start；end = timeSlots[periodEnd].end。
- weekParity=odd 仅取奇数周，even 仅取偶数周。
- 生成事件：`title=课程名`、`location`、`notes="第3-4节 · 张三 · 第5周"`、`source:"timetable"`、`courseId:"c<时间戳+序号>"`（同一门课所有实例同 id，供整门删除与重导替换）、提醒按全局默认提前量。

**解析失败降级链**：① 返回非法 JSON/无 courses → 带上错误描述自动重试 1 次；② 仍失败 → 展示模型原始返回文本，提供"复制"按钮 + 手动逐条添加入口；③ courses=0 → 提示换清晰截图或改用文字粘贴。任何一级都不静默写入空数据。

## 5. 主题与外观

### 5.1 未说出口的需求
1. **默认必须白色背景**（用户明示），夜间一键切换，入口在 ⋮ 菜单（一步可达）。
2. **背景图的可读性遮罩**：自定义背景图后，日间叠 40% 白遮罩、夜间叠 55% 黑遮罩（百分比固定，不做调节，防调花），否则花哨壁纸直接毁掉时间轴可读性——这是自定义背景最常见的翻车点。
3. 背景图从系统相册选，复制进 app 私有目录后引用（路径记入 settings.json），卸载重装需重选——设置页注明。
4. 主题落地为 CSS class（`theme-day` / `theme-night`），切换即时生效并持久化；小组件下次刷新跟随。

### 5.2 边界情况
- 背景图文件被系统清理/损坏：回退纯色背景并清除设置项，不白屏。
- 夜间模式 + 无背景图：深灰底（非纯黑）#121212，事件块用亮色描边区分。
- 超大图片选入：复制前压到屏幕宽 2 倍以内，防 WebView 卡顿。

### 5.3 验收标准
- G 首次安装 / W 打开 / T 白色背景日间主题。
- G 选定背景图 / W 切夜间 / T 图片保留且叠加暗遮罩，文字对比可读。
- G 切夜间并杀进程 / W 重开 / T 仍为夜间。

## 6. 【语音方案决策树】

点击说话键后，按序判定（每步的 UI 状态与文案固定）：

```
[点击说话键]
 ├─ 1. RECORD_AUDIO 权限未授予
 │     → 系统弹权限框；拒绝过 → 直接开文字兜底浮层
 │       文案：「麦克风权限未开。可直接打字，或用输入法自带的语音键说话」
 ├─ 2. SpeechRecognizer.isRecognitionAvailable == false（如部分国产 ROM 未装引擎）
 │     → 持久标记 speechUnavailable，本机后续点击直接跳 3
 ├─ 3. 系统识别（免费，默认主链路）
 │     UI：键→录音中「● 正在听，请说话…」→ 处理中「识别中…」
 │     ├─ 成功 → 文字入框 → 自动解析 → 确认卡
 │     ├─ ERROR_NO_MATCH / ERROR_SPEECH_TIMEOUT → 「没听清，再试一次」+「点此打字」
 │     └─ 其他错误且本次安装内累计 ≥2 次 → 持久标记 speechBroken → 自动跳 4
 ├─ 4. 云端转写（需设置中已配转写模型，如 whisper-1；未配置则直接跳 5）
 │     UI：键→录音中「● 录音中，说完点一下停止」（点击开始/点击结束，上限 60s）
 │     → 「上传转写中…」→ 成功：同 3；失败/超时/空结果 → 「转写没成功，直接打字也很快」→ 跳 5
 └─ 5. 文字兜底（永远可用）
       半屏输入卡，placeholder 引导：「试试：明天晚上8点和小王吃饭，在三里屯」
       副文案：「提示：输入法键盘上的 🎤 语音键也能用」（关键：绕开 app 内识别，借用输入法语音）
```

- 三条链路产物统一：文本 → 同一个 LLM 解析 → 同一张确认卡。
- 设置页新增「语音识别方式」状态行，显示当前生效链路（系统识别 / 云端转写 / 未配置），可手动重置 speechBroken 标记。
- 云端转写实现约束：原生 AudioRecord 录音 → multipart 上传 `/v1/audio/transcriptions`（HttpURLConnection 手写，无第三方库），录音文件用后即删。

## 7. 【小组件规格】（AppWidgetProvider + RemoteViews，无三方库）

| 尺寸 | 名称 | 显示内容 | 空态文案 |
|---|---|---|---|
| 2×2 | 下一件事 | 「14:00 高等数学 · 教一201」+「今天还有 3 件」+ 标题"今日" | 「今天没有安排」/副行「点按添加」 |
| 4×2 | 今日列表 | 今日全部事件（RemoteViews ListView，≤6 条；超出末行显示「还有 n 件」），每条「HH:mm 标题」 | 「今天没有安排，点按添加」 |
| 4×3 | 今明两天 | 上半今日列表（≤4 条），分隔行「明天」+ 明日 ≤3 条；含全天事件条 | 同上分「今天/明天均无安排」 |

- **点击行为**：2×2 与 4×2 整体点击 → 打开 app 定位到今天日视图；4×3 点击今日区/明日区分别定位到对应日（PendingIntent 模板）。小组件上不做编辑操作。
- **刷新时机**：① 事件增删改/导入课表后主动 updateAll；② 每个提醒触发后顺带刷新（复用 AlarmReceiver）；③ 每日 00:05 固定闹钟切日期（清"昨天"残留）；④ 开机广播后；⑤ onUpdate 系统触发。不监听时间 tick（费电，不做）。
- **已过事件**：在列表中灰显但不移除（今日完整感优先）。
- 深浅色：跟随系统夜间模式（WordPress RemoteViews 传主题色即可），不读 app 内主题，避免两套状态。
- 添加流程：桌面长按 → 小组件 → 三种尺寸并列可选；不实现 widget 配置页。

## 8. 超纲不做清单（本轮明确拒绝，防 scope 膨胀）

- ❌ 云同步 / 账号 / 多设备 / Web 端
- ❌ 通用"重复日程"规则引擎（RRULE）：重复只通过课表导入批量生成实例；手写日程不支持"每周重复"
- ❌ 子任务、清单、番茄钟、打卡、习惯、统计报表
- ❌ 教务系统账号抓取 / ICS 订阅 / 对接系统日历 ContentProvider
- ❌ 课表分享码 / 同学互传（WakeUp 式）
- ❌ 小组件上的直接增删改、小组件配置页、小组件实时"红线"
- ❌ 天气、农历、节假日调休、生日纪念
- ❌ 语音连续对话式多轮修改（"把明天的会改到三点"这类改日程指令）
- ❌ 图片附件、富文本笔记
- ❌ iOS / 平板适配 / 横屏

## 9. Top 5 顺手小改进（低成本高感知）

1. **事件详情卡**：点击事件块查看全部字段，可改提醒提前量（当前只能删不能看，是最大体验空洞）。
2. **保存后 5 秒可撤销**：toast「已保存 2 项 · 撤销」，误存秒救。
3. **"今天"快返**：日/周视图标题点击即回今天/本周，免翻页挨次点回来。
4. **设置页「测试」一键体检**：LLM 连通、视觉模型、转写模型分别给 ✓/✗，导入课表前先知道配置行不行。
5. **通知点击深链**：提醒通知点开直达当天日视图并滚动定位到该事件，而不是 app 首页。
