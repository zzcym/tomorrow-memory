### 写作规范：六段讲述结构 + 五层下挖阶梯（读 15 分钟，本周所有讲稿按这个写）

1. **六段结构**（每个项目的 `talk-*.md` 都按这六段写，段落标题原样用）：

2. **五层下挖阶梯**（`drill.md` 每个项目按层写，每层 ≥3 问，三个项目合计 ≥45 问）：
    - L1 事实层：这个数字/配置/模块具体是什么，记在哪个文件
    - L2 选择层：为什么是这个选择，替代方案是什么，你怎么排除的
    - L3 权衡层：这个选择的代价；什么条件下结论会反过来
    - L4 失败层：这条路上真出过什么问题，你怎么定位的，有没有没解决的
    - L5 扩展层：数据 ×10 / 模型从 1.5B 到 7B / 上线到真实并发，**哪个先崩**，为什么

3. 每问四段写全：**问 / 我的 60 秒答（口播稿，不是要点）/ 证据出处（文件或截图路径）/ 漏洞标记**（`已验证` / `量级估计` / `没做过`）。**"没做过"这一栏必须存在且不许全填"已验证"**——面试官一句"这个你测过？"就能把假答案打成零分，而"我没测，但我推测是 X，测法是 Y"是加分。

### 三道经典追问：差答案 vs 好答案对照（照这个结构重写你自己的版本）

**Q1 "LoRA 的 rank 为什么选 16？"**
- 差答案：① "常见值/默认值"（等于没答）② "越大效果越好，显存不够"（一句都对但没信息）③ 只报一个数字，说不出替代方案。
- 好答案要含五件东西：
    1. 先说 r 到底决定什么：ΔW = BA 的秩，可训参数量随 r 线性（单层约 `r*(d_in+d_out)`），容量与 adapter 体积一起涨。
    2. 我的对照：`r=4 / 8 / 16 / 32` 同一份数据、同一 lr、同一 target_modules，指标差多少（写量级 + 出处；没留表就写"未量化"并说明当时为什么没留）。
    3. 为什么不选小的：r=4 时具体哪个能力没学到（举一个输出层面的现象，不是"效果差一点"）。
    4. 为什么不选大的：r=32 增益不到一个可感知的量级，但 adapter 体积翻倍、更容易过拟合偏好数据。
    5. 收尾的加分句：换 r 时我锁的是 `scaling=alpha/r` 这个比值，不锁它扫出来的差异里混着有效学习率的效应——**这一句是区分"用过 LoRA"和"懂 LoRA"的分水岭**。
- 第 5 层追问："7B 上还锁 alpha=32 吗？"答：r 与 alpha 要重扫，因为基座容量变大后旁路更新的相对占比变了；我的做法是先固定 `alpha/r=2` 再扫 r（这是量级判断，我没做完整消融，会诚实说出来）。

**Q2 "reward hacking 出现过吗？"**
- 差答案：① "没有，我 KL 控制得比较好"（做过 RL 的人不会这么说，等于自曝）② "有，输出变长了"——没有判据、没有修法、没有遗留。
- 好答案的五步：
    1. 一句确认："出现过，是格式项被吃掉的版本。"
    2. 我怎么发现：reward / 平均输出长度 / KL 三条画在同一张图上，看到"reward 涨但正确率平、长度同向上"。
    3. 判据（要能背）：**reward 与长度同向上升、reward 与可验证正确率脱钩 = hacking 信号**；只看 reward 曲线一定会被骗。
    4. 我做了什么：把 reward 拆子项归因 → 格式校验收紧到"只认最后一个答案" → 加长度惩罚 → KL 系数拉大一档 → 必要时重训/重校 RM。
    5. 遗留：judge 与人工盲评的一致率我现在还不满意，量级大概是多少、当时只抽了 N 条人工复核。
- 抽象收口一句（背下来）：**"hacking 不是模型坏了，是我的奖励函数写漏了——RM 分布外的区域，策略一定会找到。"**

**Q3 "KL 系数怎么调的？"**
- 差答案：① "用的 0.2"（报数不讲法，第二层追问就崩）② 把 PPO 的 KL 惩罚系数和 DPO 的 β 混成一谈还不声明口径。
- 好答案的六步：
    1. **先定术语与位置**：PPO 里 KL 是逐 token 加在 reward 端的惩罚（系数常记 β/KL-coef）；DPO 里的 `beta`（TRL 默认量级 0.1）是偏好损失里偏离参考策略的强度；GRPO 的常见实现是 loss 端的 `kl_coef`。**三个不是同一个旋钮**，先说清自己在讲哪一个——这一句说出来，面试官就知道你真配过。
    2. 我盯什么信号：健康 = reward 上行 + KL 在受控区间小幅波动；病态 = KL 单调上涨且 reward 不涨，或 KL 几乎不动而 reward 猛涨（学不动或在钻空子）。
    3. 我的取值量级与起点：从一个小值起步往上调，一次只动一档，其余锁死。
    4. 代价双向：调太大 → 学得慢、贴回基座、能力上限被压；调太小 → 语言风格漂移、复读、更易 hacking。
    5. 可执行纪律（这句最值钱）："我把 **KL 连续 N step 单调上升且 reward 不涨** 设成自动停训条件"——把玄学变成开关。
    6. 诚实遗留：我只做了两档对照，没做系统扫参；所以我讲不了最优值，只能讲我为什么不用极端值。

> 注：上面三题的"好答案"是同一个模板：**定位术语 → 我盯的信号 → 我的量级 → 双向代价 → 遗留问题**。任何一层缺了都会被判成"背过没做过"。本周 `drill.md` 里 45 问全部按这个五段结构写，写完自查一遍：有哪几问只有前两层，那几问就是你面试时的出血点。

1. 新建 `week15/day2/bt_rm.py`：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class ScalarRM(nn.Module):
    """极简 RM：序列特征 -> 线性回归头 -> 标量分数。
    真实 RM 是 基座 + pool/末 token -> Linear(1)，这里只写损失相关部分。"""
    def __init__(self, dim: int):
        super().__init__()
        self.head = nn.Linear(dim, 1)

    def forward(self, feats):                  # feats: (B, dim)
        return self.head(feats).squeeze(-1)    # -> (B,)

def bt_loss(r_chosen, r_rejected, label_smoothing: float = 0.0):
    """Bradley-Terry / 成对逻辑回归: -log sigmoid(r_c - r_r)。
    label_smoothing>0 时混一点反向项: 偏好标注一定有误标。"""
    diff = r_chosen - r_rejected
    loss = -F.logsigmoid(diff)
    if label_smoothing > 0.0:
        loss = (1.0 - label_smoothing) * loss + label_smoothing * (-F.logsigmoid(-diff))
    return loss.mean()
```

2. 新建 `week15/day2/test_bt.py`，**四个断言自己先想**：① 与手写式 `-log σ(Δr)` 逐条一致；② margin 拉开时损失单调下降；③ 梯度符号（对 chosen 为负、对 rejected 为正）；④ margin 为 0 时损失恰好是 `ln2`。

```python
from bt_rm import ScalarRM, bt_loss

torch.manual_seed(0)                              # 种子写死，失败才能复现

fc, fr = torch.randn(8, 16), torch.randn(8, 16)

loss = bt_loss(rc, rr)

manual = -(rc - rr).sigmoid().log().mean()
assert torch.allclose(loss, manual, atol=1e-6); print("formula OK")
assert bt_loss(rc + 5.0, rr) < loss; print("margin-monotone OK")
a = torch.tensor([2.0, -1.0], requires_grad=True)
b = torch.tensor([0.5, -3.0], requires_grad=True)
bt_loss(a, b).backward()
assert (a.grad < 0).all() and (b.grad > 0).all(); print("grad-direction OK")
assert abs(bt_loss(torch.zeros(4), torch.zeros(4)).item() - math.log(2)) < 1e-6
print("zero-margin=log2 OK")
assert bt_loss(torch.tensor([50.0]), torch.tensor([-50.0])).item() < 1e-9
print("separable->0 OK")
print("BT TESTS OK")
```

## 任务 2：手撕 2 · GRPO 组内优势（约 110 分钟）

1. 新建 `week15/day4/grpo_adv.py`：

```python
import numpy as np

def grpo_advantage(rewards, eps: float = 1e-6):
    """rewards: (n_prompts, G) —— 同一 prompt 采 G 个输出的规则奖励。
    返回 (adv, keep): adv 同形状，keep 标记每组是否参与更新。
    组内标准差为 0（全对/全错）时优势无信息，整组丢弃。"""
    rewards = np.asarray(rewards, dtype=np.float64)
    mean = rewards.mean(axis=1, keepdims=True)
    std = rewards.std(axis=1, keepdims=True)          # 总体标准差, ddof=0
    adv = (rewards - mean) / (std + eps)
    keep = (std.squeeze(1) > 1e-8)
    return adv * keep[:, None], keep
```

## 任务 2：手撕 3 · LoRA merge 与回滚（约 100 分钟）

1. 把 Week 14 的 `lora_layer.py` 复制进 `week15/day5/`，并补上 `unmerge`（面试里"merge 之后怎么回滚"的标准实现之一）：

```python
    @torch.no_grad()
    def unmerge(self):
        """减回同一片 delta。float64 下可复原到 1e-9 量级；
        bf16 基座上减回的残差不可忽略 —— 所以 merge 前一定留一份未 merge 权重。"""
        self.base.weight.data -= self.scaling * (self.B @ self.A)
        self.merged = False
```

2. 新建 `week15/day5/test_merge.py`：

```python
import copy, torch, torch.nn as nn
from lora_layer import LoRALinear

torch.manual_seed(7)                                    # 种子写死
base = nn.Linear(64, 32).double()
layer = LoRALinear(base, r=8, alpha=16).double()
x = torch.randn(4, 64, dtype=torch.float64)
snapshot = copy.deepcopy(base)                          # 回滚凭据: merge 前的基座副本

with torch.no_grad():
    layer.A.normal_(0, 0.05); layer.B.normal_(0, 0.1)
ref = layer(x).clone()
layer.merge()
assert torch.allclose(base(x), ref, atol=1e-5); print("merge-equiv OK")
assert layer.merged and torch.allclose(layer(x), base(x), atol=1e-12); print("no-double-path OK")

layer.unmerge()
assert torch.allclose(base.weight, snapshot.weight, atol=1e-9); print("unmerge-recover OK")
assert layer(x).dtype == ref.dtype and torch.allclose(layer(x), ref, atol=1e-5)
print("re-bypass OK")

back = LoRALinear(copy.deepcopy(snapshot), r=8, alpha=16).double()
assert torch.allclose(back(x), snapshot(x), atol=1e-12); print("reload-base-rollback OK")
n_ab = sum(p.numel() for p in layer.parameters() if p.requires_grad)
assert n_ab == 8 * (64 + 32) and n_ab < sum(p.numel() for p in snapshot.parameters())
print(f"adapter-size-ratio OK ({n_ab} vs {sum(p.numel() for p in snapshot.parameters())})")
print("MERGE TESTS OK")
```

**完成判据**：打印 6 个测试名 + `MERGE TESTS OK`，从空文件到全绿 **≤40 分钟**；NOTES 里两条口径各 ≥2 句；`adapter-size-ratio` 那行打印出来的两个数字抄进 NOTES（讲"adapter 只有几 MB"时要用真实量级）。

> 注：这题的杀手追问是"你 merge 过之后想换回原来的基座怎么办"。三种答法分高下：低——"重训"；中——"把 delta 减回去"（就是今天写的 `unmerge`，要能立刻说出它在低精度下留残差）；高——**"我 merge 前一定留一份未 merge 的基座副本，回滚是换权重文件而不是做算术，减 delta 只是没有副本时的补救"**。判据里的 `reload-base-rollback OK` 就是在逼你走第三种路径。

## 三、常见问题与纪律

- **某天崩了怎么办？** 不熬夜追。未完成项按「天-任务号」写进 `gaps.md`，Day 7 前 1 小时与缓冲就是给它们的。连续两天崩，砍 Day 3 任务 3（八股回补）和 Day 5 任务 4（台账跟进），**保刷题、三份讲稿 + drill、集中投递、模拟面**。
- **投递石沉大海怎么办？** 这是常态不是信号。唯一正确的动作是继续按日计划走 + 把 JD 里你对不上的关键词计数（Day 3 任务 4 那一栏）。**同一个要求连续被 ≥5 家拒**才叫信号——多半是"分布式训练"或"论文/竞赛"，处理办法见总计划风险 3：横移投数据构造 / 评测 / Agent 后训练岗（技能重叠约八成、竞争小得多），进大厂再转组是常规路径。不许因为没回复就回去改简历第 8 版或重跑实验。
- **单题/单点卡多久放手？** 刷题按今天限时（15-40 分钟），到点看题解只看到思路、第二天重做才计数。非刷题卡点 40 分钟无解就写 NOTES + gaps 跳过；**开卡卡点例外：30 分钟没跑起来就关机**，已花的钱算沉没。
- **卡时与钱**：本周上限 2h、预估 ¥3-5。开卡前 `rerun.sh` 必须已存在；跑完即关机，确认"已关机"；**任何时候不点销毁**。计费明细截图进 `review.md`。
- **模拟面不是测试**：它唯一作用是暴露"讲不出"。第 3 次要盯的还是**被打断后的恢复能力、空转时长、有没有结论句**，不是通过率。
- **数字纪律（本周最容易破功）**：讲稿与 drill 里的每个数字要么有出处路径，要么写"量级/约"，要么写"未量化"。补跑没做成也不许回填精确值——面试官追问三个细节就露馅，一露馅全盘皆输。
- **AI 工具的边界**：允许它解释报错、给算法思路方向、review 你写完的代码、帮你把口播稿改顺；**不允许**替你 AC 题、替你写项目经历、替你答五层下挖。现场手撕与追问时你身边没有它。
