### 写作规范：失败案例条目模板 + 6 条样板（读 15 分钟，本周所有条目按这个格式写）

条目模板（五段，粘到 fail-log.md 顶部当规范）：

```markdown
### F-<编号> <一句话标题，≤20 字>
- 阶段与标签：M2 SFT / M2 DPO / M3 GRPO / M4 tutor；标签 [lr] [数据] [mask] [显存] [工程环境] [评测] [reward]

- 修复：改了哪个配置或哪行代码；改后的变化写"量级 + 出处文件路径"，没留记录就写"未量化"
- 30 秒讲法：结论在前的两三句面试口径，朗读 ≤40 秒

```

下面 6 条是**格式样板**，用来告诉你"每一段该写多具体、什么算证据"。**其中的数值只是示意，说明这一格该放什么类型的内容——你写自己那份时必须换成你日志/wandb 里的真实记录，示意值一条都不许抄进简历或 fail-log。**

**F-01 train loss 三条曲线全平，可训参数量是 0（M2 · SFT）**
- 现象：LoRA 跑了 300 step，train loss 几乎不动，grad norm 恒为 0，看起来"训练在走但什么都不学"
- 定位：按 lr→数值精度→数据→初始化 查；第 0 步先加一行打印 `sum(p.numel() for p in model.parameters() if p.requires_grad)`，结果是 0，再对比模型层名，发现 `target_modules` 里的模块名在这个模型上不存在（不同模型族的投影层命名不一样）
- 修复：改成该模型真实的投影名，可训参数从 0 变成百万量级（`出处：m2-sft/README.md` 的参数打印），loss 才开始下降
- 30 秒讲法：我第一次 SFT 训练 loss 完全不动，先在优化器上加了一行可训参数量打印，发现是 0，原因是 LoRA 挂载的模块名写错、一个参数都没注册上。从那以后我的训练脚本第一步永远是打印可训参数表，这是我排查 loss 不降的第一道闸门。
- 追问预案：会问"怎么快速确认 LoRA 挂上了"——答：`model.print_trainable_parameters()` 或直接遍历 named_parameters 按前缀分组统计；再说 adapter 权重里 B 全零、A 随机，加载后先看 B 的范数是否非零。

**F-02 SFT 后模型只会复述问题（M2 · SFT · mask）**
- 现象：训完的模型对"用一句话解释 XX"这类指令，输出先把问题重抄一遍再空行，eval loss 看着还行
- 定位：拿一个 3 轮对话样本把 label 解码出来打印，发现 prompt 段的 label 不是 -100——数据格式化时走的是"整段拼接再全算 loss"的路径，等于教模型复述指令
- 修复：改用 `tokenizer.apply_chat_template` 生成角色分段，再按 assistant span 置 label，只对 assistant token 算交叉熵
- 30 秒讲法：我最印象深的一次是模型训完只会复读问题。表面看 loss 正常，其实是 label mask 没生效，prompt 也进了 loss。修复之后我把"打印一个样本的 label span"加进了训练前的必查清单。
- 追问预案：会问"为什么只算 answer"——答：instruction 在推理时是已知条件，学它等于浪费容量且教出复述行为；再补一句 packing 的副作用（跨样本注意力泄漏）。

**F-03 手拼 chat template 导致推理格式漂移（M2 · SFT · 工程环境）**
- 现象：训练时输出格式整齐，接上线上推理后模型偶尔多吐一个换行、或把角色标记当正文续写
- 定位：把训练用的字符串和推理侧 `apply_chat_template` 的结果逐字符 diff，发现训练里手拼的模板少了结束标记，两边编码不一致
- 修复：训练与推理统一走 `tokenizer.apply_chat_template`，禁止手拼字符串；重训后 A/B 那 30 个场景的格式非法率显著下降（未量化，看 A/B 表）
- 30 秒讲法：我的模板 bug 不是训练崩，是训练和推理两侧各自拼模板、拼得不一样。这类问题曲线看不出来，只有把两边字符串做 diff 才现形，所以我现在的纪律是模板只有一处来源。
- 追问预案：会问"ChatML 风格标记具体是什么"——答 Qwen 系列的角色起始/结束特殊 token，并说明用错 tokenizer 的 template 会让 SFT 白训。

**F-04 DPO 里 chosen 和 rejected 的对数概率一起掉（M2 · DPO · reward）**
- 现象：训练后期 margin（chosen - rejected）在涨，但两条 logprob 曲线都在往下走，chosen 的下降速度比 rejected 慢
- 定位：查 TRL 的指标口径，确认 margin 涨是靠"rejected 掉得更快"实现的；这不是学到偏好，而是同时打压两者
- 修复：把 lr 再降一档、缩短 epoch、混入 SFT 损失（或换 SimPO/KTO 的思路做对照），并把"两条 logprob 必须一起看"写进监控清单
- 30 秒讲法：DPO 最容易骗人的指标是 reward margin。我见过 margin 上升但 chosen 概率也在跌的情况，这时候模型其实是在变得更不擅长说人话，不是在变好。所以我看 DPO 曲线一定看三条：margin、chosen logprob、rejected logprob。
- 追问预案：会问 β 的作用——答：β 控制偏离 ref 的强度，太大学不动、太小易过拟合偏好并让语言退化，我用的量级是 0.1。

**F-05 GRPO 组内优势全零，reward 曲线一条直线（M3 · GRPO · reward）**
- 现象：reward 均值在前若干 step 不升，KL 却慢慢飘高，看起来"在优化但没方向"
- 定位：把组内 reward 打印出来，发现同一 prompt 的 G 个采样结果全对或全错，`std` 为 0，`(r_i - mean)/std` 归一化后整组优势为 0（分母处理不同实现会给 0 或小 eps，行为不同，要确认你用的框架）
- 修复：提高采样温度或换难度更合适的题（准确落在 0.3-0.7 区间的题最有信息量）、增大 G、丢弃零方差组
- 30 秒讲法：我 GRPO 第一次不涨的原因很简单——题目太简单，全组都做对，组内基线等于零信号。之后我把"题目难度分布"当成 RLVR 的第一超参来调。
- 追问预案：会问"怎么知道该扔掉哪些题"——答：先采一轮统计每题通过率，保留中间段、去掉两端；再说这也解释了为什么规则奖励要设计成部分可给分。

**F-06 输出长度暴涨而 reward 平（M3 · GRPO · reward hacking）**
- 现象：中后期平均输出长度快速上冲、reward 不再涨，抽样看内容是重复句式与堆砌步骤
- 定位：把 reward 拆成子项（正确性 / 格式 / 长度）分别看，发现格式项被"长答案里重复出现合法格式"吃掉；长度分布曲线与 reward 曲线放同一张图就是证据
- 修复：加长度惩罚项或收紧格式校验（只认最后一个答案），必要时重训 RM/验证器；KL 系数调大一点把策略拉回参考附近
- 30 秒讲法：我亲眼见过一次典型 reward hacking：长度暴涨、reward 走平。判断依据是长度与 reward 的解耦，而不是单看 reward 涨没涨。修法要么改奖励函数堵住捷径，要么加 KL 约束。
- 追问预案：会问 KL 系数怎么定——答：没有万能值，我的做法是盯 KL 曲线，健康时受控小幅波动，一旦单调上涨且 reward 不涨就加大约束；这也是为什么我保留了那条不收敛曲线。

> 注：这 6 条样板的共同点是**每条都写到了"我怎么知道的"**，而不只是"我改了什么"。面试里区分度的来源是排查顺序与证据，不是修复动作本身。你写自己那 20 条时，如果某条的"定位"段只有一句"改了配置就好了"，那条等于没写。

## 任务 3：八股第二批启动 · RL 基础（约 120 分钟）

```python
import torch, torch.nn as nn

class LoRALinear(nn.Module):
    """base 冻结 + 低秩旁路。ΔW = B @ A, 形状 (out_f, in_f) 与 base.weight 同形"""
    def __init__(self, base, r=16, alpha=32, dropout=0.0):
        super().__init__()
        self.base, self.r, self.scaling, self.merged = base, r, alpha / r, False
        for p in self.base.parameters():
            p.requires_grad = False                              # 基座冻结
        in_f, out_f = base.in_features, base.out_features
        self.A = nn.Parameter(torch.randn(r, in_f) * 0.05)       # A: (r, d_in) 随机初始化
        self.B = nn.Parameter(torch.zeros(out_f, r))             # B: (d_out, r) 初值必须为 0
        self.drop = nn.Dropout(dropout)

    def forward(self, x):
        y = self.base(x)
        if self.merged:
            return y
        return y + self.drop(x) @ self.A.t() @ self.B.t() * self.scaling

    @torch.no_grad()
    def merge(self):
        self.base.weight.data += self.scaling * (self.B @ self.A)
        self.merged = True
```

1. 新建 `week14/day3/my_adamw.py`：

```python
import numpy as np

def adamw_step(params, grads, m, v, t, lr=1e-3, b1=0.9, b2=0.999, eps=1e-8, wd=0.01):
    """原地更新 params。t 从 1 开始计数。wd 是解耦权重衰减(AdamW),不是 L2 进梯度"""
    for i in range(len(params)):
        m[i] = b1 * m[i] + (1 - b1) * grads[i]
        v[i] = b2 * v[i] + (1 - b2) * grads[i] ** 2
        m_hat = m[i] / (1 - b1 ** t)              # 偏差修正
        v_hat = v[i] / (1 - b2 ** t)
        params[i] -= lr * (m_hat / (np.sqrt(v_hat) + eps) + wd * params[i])
```

2. 新建 `week14/day3/test_adamw.py`：同一个二次函数 + 同一个初始点，float64，跑 20 步，与 `torch.optim.AdamW`（`betas=(0.9,0.999), eps=1e-8, weight_decay=0.01, lr=1e-3`）逐步对拍。

```python

from my_adamw import adamw_step

np.random.seed(0); torch.manual_seed(0)          # 两边共用同一个初始点, 否则无从对齐
target = np.array([1.0, -2.0, 0.5, 0.0])
w_np = np.random.randn(4).astype(np.float64)
w = torch.tensor(w_np.copy(), requires_grad=True)
tgt = torch.tensor(target, dtype=torch.float64)
opt = torch.optim.AdamW([w], lr=1e-3, weight_decay=0.01)
m, v = [np.zeros_like(w_np)], [np.zeros_like(w_np)]
max_diff = 0.0
for t in range(1, 21):                            # 同一个二次目标, 梯度 = w - target
    adamw_step([w_np], [w_np - target], m, v, t)
    opt.zero_grad(); (0.5 * (w - tgt).pow(2).sum()).backward(); opt.step()
    max_diff = max(max_diff, np.abs(w_np - w.detach().numpy()).max())
    print(t, max_diff)
assert max_diff < 1e-6, f"AdamW 对拍失败 max_diff={max_diff}"
print("ADAMW CROSSCHECK OK")
```

## 任务 2：手撕 3 · numpy 写 decoder block 前向（约 110 分钟）

1. 新建 `week14/day4/block_np.py`。要求：RMSNorm → 多头因果自注意力 → 残差 → RMSNorm → SwiGLU 式 FFN → 残差，形状 (T, C)，**float64**，种子写死。

```python
import numpy as np

T, C, H, FF = 6, 16, 4, 64
DK = C // H

def silu(z): return z / (1.0 + np.exp(-z))

def rmsnorm(x, w, eps=1e-6):
    return x * w / np.sqrt((x * x).mean(-1, keepdims=True) + eps)

def softmax(x):
    x = x - x.max(-1, keepdims=True)
    e = np.exp(x)
    return e / e.sum(-1, keepdims=True)

def mha(x, p):
    q, k, v = x @ p["Wq"], x @ p["Wk"], x @ p["Wv"]
    mask = np.triu(np.full((T, T), -np.inf), k=1)
    outs = []
    for h in range(H):
        s = lambda t: t[:, h*DK:(h+1)*DK]
        a = softmax(s(q) @ s(k).T / np.sqrt(DK) + mask)
        outs.append(a @ s(v))
    return np.concatenate(outs, axis=-1) @ p["Wo"]

def block(x, p):
    x = x + mha(rmsnorm(x, p["ln1_w"]), p)
    h = rmsnorm(x, p["ln2_w"])
    return x + (silu(h @ p["Wg"]) * (h @ p["Wu"])) @ p["Wd"]

def make_params():
    r = np.random.default_rng(42)            # 写死: 对拍要同一组权重
    W = lambda a, b: r.normal(0, 0.02, (a, b))
    return dict(ln1_w=np.ones(C), ln2_w=np.ones(C), Wq=W(C, C), Wk=W(C, C),
                Wv=W(C, C), Wo=W(C, C), Wg=W(C, FF), Wu=W(C, FF), Wd=W(FF, C))
```

2. 新建 `week14/day4/test_block.py`，三个断言：① 输出形状 (T, C)；② **因果性**：把 `x[T-1]` 换成随机值，前 T-1 行输出与换之前逐元素相等（atol=1e-12）；③ 与 torch 对拍：`max_abs_diff < 1e-9`。

```python
import numpy as np, torch
from block_np import block, make_params, T, C, H, DK

def torch_block(x, p):                       # 同一套算式用 torch float64 再写一遍
    t = lambda a: torch.tensor(a, dtype=torch.float64)
    x, p = t(x), {k: t(v) for k, v in p.items()}
    rms = lambda v, w: v * w / torch.sqrt((v * v).mean(-1, keepdim=True) + 1e-6)
    silu = lambda z: z / (1 + torch.exp(-z))
    mask = torch.triu(torch.full((T, T), float("-inf"), dtype=torch.float64), 1)
    def mha(v):
        q, k, vv = v @ p["Wq"], v @ p["Wk"], v @ p["Wv"]
        s = lambda z: z[:, h*DK:(h+1)*DK]
        outs = []
        for h in range(H):
            a = torch.softmax(s(q) @ s(k).T / float(DK) ** 0.5 + mask, dim=-1)
            outs.append(a @ s(vv))
        return torch.cat(outs, -1) @ p["Wo"]
    v = x + mha(rms(x, p["ln1_w"]))
    hh = rms(v, p["ln2_w"])
    return (v + (silu(hh @ p["Wg"]) * (hh @ p["Wu"])) @ p["Wd"]).numpy()

p = make_params(); x = np.random.default_rng(1).normal(size=(T, C))
y = block(x, p)
assert y.shape == (T, C); print("shape OK")
x2 = x.copy(); x2[-1] = np.random.default_rng(99).normal(size=C)
assert np.allclose(y[:-1], block(x2, p)[:-1], atol=1e-12); print("causal OK")
d = np.abs(y - torch_block(x, p)).max(); print("max_abs_diff =", d)
assert d < 1e-9; print("BLOCK CROSSCHECK OK")
```

3. 跑 `cd E:/study/posttrain/week14/day4 && python test_block.py`，期望打印 `shape OK` / `causal OK` / `BLOCK CROSSCHECK OK`，并把 max_abs_diff 的实际量级记进 NOTES。

**完成判据**：三个 OK 全部打印；**从空文件到全绿 ≤40 分钟**；NOTES 里写清"多头是怎么切的（reshape 还是列切片）""为什么 mask 必须在 softmax 之前"。

> 注：这份 numpy/torch 两边故意写成同一套算式，对拍对的是**实现一致性**，不代表某个真实模型的结构（Qwen/LLaMA 的 FFN 维度比例、是否带 bias、有没有 RoPE 各不相同——这里连位置编码都没写）。面试被问到就讲"这是我为对拍写的最小可比版本，位置编码交给 embedding"，比假装它是 LLaMA 稳。

## 三、常见问题与纪律

- **某天崩了怎么办？** 不熬夜追。未完成项按「天-任务号」写进 `gaps.md`，Day 7 的前 1 小时和缓冲就是给它们的。连续两天崩，砍 Day 4 任务 5（补跑脚本准备）和 Day 5 任务 4（台账跟进），**保刷题、手撕、fail-log、模拟面**。
- **单题/单点卡多久该放手？** 刷题按今天限时（25/35 分钟），到点看题解并标"抄会"，别在一道题上烧 90 分钟——那是"手感恢复期"最贵的错。非刷题的技术卡点 40 分钟无解就写 NOTES + gaps 并跳过。
- **卡时与钱**：本周上限 4h、预估 ¥6-10。**开卡前先看 `rerun.sh` 有没有写完**；跑完即关机，确认控制台显示"已关机"；**任何时候不点销毁**。超了就说明忘关机，去看计费明细，并在 `review.md` 记一笔。
- **别把模拟面当成测试**：它的唯一作用是暴露"讲不出"。第 2 次比第 1 次（Week 13）要盯的指标是**空转时长和被打断次数**，不是通过率。
- **数字纪律**：简历、fail-log、讲述稿里出现的每个指标都要有出处文件。没记录就写"量级/约"或"未量化"，**绝不写精确的假数字**——面试官追问三个细节就露馅，一露馅全盘皆输。
- **AI 工具的边界**（求职周仍然适用）：允许它解释报错、给题解思路前的提示方向、review 你写完的代码；**不允许**让 AI 直接 AC 你的题、替你写 fail-log 的真实经历、替你答八股。你面的是训练岗，现场手撕时你身边没有它。
- **诚信与合规**：博客和 repo README 继续标清哪些是复现、哪些是自己写的；引用数据集要留许可与来源。这条不会救你于面试，但会救你于 offer 之后的背调。
