# 明日记忆 · 安卓 App 需求文档（v1）

> 来源：用户口头需求（2026-09-16）整理。日期截止：**次日交付可用的查词 + 背词 App**。
> 执行者按本文档执行；与用户原话冲突时以原话为准。

## 0. 背景与现状（已核实）

- 「明日记忆」= 当前仓库 monorepo：Next.js 网页版 + Hono 后端 + SQLite/PG，功能含查词、单词本、FSRS 背词、打卡、AI 教学等。
- **服务端已部署在阿里云**（106.15.0.124，CI: main push → GHCR 镜像 → SSH 部署，Caddy HTTPS）：`https://tmword.xyz` 实测 200。
- **决策：App 与网页版共用该服务端**（用户已倾向于"共用"，且要求上线后数据留存——同账号同数据库天然满足）。App 不新建后端。

## 1. 服务端契约（App 直接消费，不改服务端）

Base URL：`https://tmword.xyz`，JSON UTF-8。鉴权 `Authorization: Bearer <JWT>`（登录返回，30 天有效）。

| 功能 | 端点 | 说明 |
|---|---|---|
| 发验证码 | POST `/api/send-code` {phone} | 手机号校验 `1[3-9]\d{9}`；60s 冷却 |
| 登录 | POST `/api/login` {phone, code} 或 {phone, password} | → `{token, phone, hasPassword, nickname, avatar}`；开发万能码 `12345`（生产若未配 AUTH_DEV_MASTER_CODE 则不可用；生产用户用真实短信或密码） |
| 当前用户 | GET `/api/me` | Bearer |
| 查词 | GET `/api/lookup?word=&direction=auto` | 匿名可用；→ `{word, phonetic, translation, definition, groups:[{pos,meanings[]}], exchange{}, examples:[{en,zh}]}`；zh→en 未找到返回 404；IP 限流 30/min |
| 单词本 | GET `/api/wordbook` → `{data:[{word,addedAt}]}`；PUT `/api/wordbook` {data}（全量覆盖，≤20000 条） | auth；查词后自动加入由客户端控制 |
| 今日复习 | GET `/api/review/today` → `{total, dueToday, queue:[{word,retrievability,elapsedDays}]}` | auth |
| 复习评分 | POST `/api/review` {word, rating:1-4}（1 忘记/2 困难/3 良好/4 轻松） | auth |
| 打卡 | GET `/api/checkin/status`、POST `/api/checkin` | auth |
| 档案 | GET/PUT `/api/profile` | auth（昵称/头像/每日目标） |

## 2. 范围

**做**：查词（首页）、单词本（增删查）、背单词（FSRS 卡片式）、登录/注册（手机号+验证码/密码）、桌面小组件（搜索框）、用户数据持久化（服务端为准 + 本地缓存兜底）。
**不做**（本期）：AI Agent 对话、测评、学情分析、打卡/头像（登录后能看到即可，不专门做页面）、iOS、上架。

## 3. 用户功能需求

### 3.1 首页 = 查词（用户明确指定）
- 白色背景、极简。**页面底部居中一个圆角搜索框**（输入法弹出时贴住键盘）。
- 顶栏**右上角三条横线菜单**（汉堡），点开为抽屉/菜单，承载全部其他入口：背单词、单词本、登录/我的、设置（关于）。
- 输入回车/点查 → **结果直接展示在首页**：
  - 单词名与释义**黑色加粗**（用户明确指定）；音标灰色；词性分组清晰；例句列表样式得体（设计定）。
  - 查词结果自动加入单词本（与网页版行为一致），给出轻提示；重复查同词不重复添加。
- 最近查词本地留存（离线可看）；下拉或清空按钮管理。

### 3.2 登录 / 用户数据（重点）
- 首次启动未登录也可查词（匿名限流内）；背词/单词本需要登录。
- 登录页：手机号 + 验证码（发送按钮倒计时 60s），或手机号 + 密码；支持设密码（若服务端 hasPassword=false 时提示可跳过本期）。
- **JWT 持久化**：原生 SharedPreferences 与 WebView localStorage 双写；App 冷启动/进程被杀后仍保持登录；token 失效（401）自动登出并引导重新登录。
- **数据保存链路（重点测试项）**：
  - 单词本：查词自动 add → 服务端 wordbook 全量覆盖式 PUT 的并发冲突要避免（客户端保存权威副本 + 变更队列，先本地后同步，失败重试）。
  - 背词评分：POST /api/review 成功才算完成；网络失败时卡片保持当前状态并提示重试，不允许静默丢失评分。
  - 卸载重装后登录即可恢复全部数据（服务端为准）——测试项。

### 3.3 背单词（卡片式，产品 agent 设计）
- 入口在抽屉菜单；显示"今日待复习 N"；卡片翻面交互；四档评分（1 忘记/2 困难/3 良好/4 轻松）映射 API rating；完成后有结算页（今日 done）。
- 无到期卡片时的空态（"今日已清空，明天再来"）。

### 3.4 桌面小组件（用户明确指定：只需一个搜索框）
- 2×2 左右的搜索框样式小组件：点任意位置 → 拉起 App 并**直接聚焦搜索框并弹键盘**；输入查询走正常查词流程。
- 深浅色自适应；Android 8+ 可用。

### 3.5 非功能
- 白色背景（用户指定）；系统返回键/手势正确；弱网与断网有明确提示（不白屏）；查词本地缓存（最近 200 条）离线可用。
- 安全：JWT 只存本机；HTTPS 唯一；不日志敏感信息；小组件不含敏感数据。

## 4. 技术方案

- 形态：与「明日日程」app 相同的成熟栈——**原生 Android 壳 + WebView(本地 HTML/JS/CSS) + Java 桥 + 无 Gradle 构建链**（aapt2/javac/d8/apksigner，工具链已就绪）。前端为本次新写的移动 UI（不复用 Next.js 页面）。
- 目录：`mobile-memory/`。API 全部走线上 tmword.xyz（cleartext 关闭，仅 HTTPS）。
- 小组件：AppWidgetProvider + RemoteViews（TextView 模拟搜索框），点击 PendingIntent 带 `focus=search` extra 打开 MainActivity。

## 5. 交付与验收

- 交付：`mobile-memory/明日记忆.apk`（已签名，可覆盖安装）+ 测试报告。
- 验收（用户次日可用为标准）：
  1. 安装 → 登录（真实验证码或万能码）→ 查词出结果且加粗 → 自动进单词本 → 服务端可见（与网页版互通）。
  2. 背词卡片完整走完一轮今日队列，评分后 FSRS 进度变化（服务端可查）。
  3. 杀进程重开：登录态、最近查词仍在。
  4. 桌面小组件点击 → 直接进入可输入状态。
  5. 断网时查词有提示、最近查词离线可看；恢复网络自动恢复。
- 测试流程（用户指定"标准流程"）：功能（黑盒 GUI 全流程）+ 白盒（单测：请求构造/token/缓存/并发队列）+ 可靠性（断网/超时/401/双击重复提交）+ 可服务性（401 登出、限流提示、服务端 5xx 兜底文案）+ 性能（冷启 <2s、查词 P95 <1.5s 感知、滚动不卡）+ 安全（HTTPS、token 存储、日志脱敏、小组件无敏感数据）。
