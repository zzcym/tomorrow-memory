# 明日记忆 · 背单词卡片 & 查词结果 交互设计（v1，2026-09-16）

> 供单人一晚实现。前提：WebView 手写 HTML/JS/CSS，无框架；服务端契约不改（见 APP-REQUIREMENTS.md §1）。
> 所有元素均为纯 HTML+CSS+原生 JS 可直接实现，无动画库、无组件库。

---

## 1. 背词流程状态机

```
进入 → [S0 未登录] → 登录后重进
     → [S1 加载] GET /api/review/today
          ├─ 失败 → [S1E 错误态]（重试按钮）
          ├─ dueToday=0 → [S7 结算页]（空队列文案）
          └─ 成功 → [S4 正面] ⇄ 点击卡片翻面 → [S5 背面]
                                        ↓ 点任一评分按钮
                                   [S6 提交中] POST /api/review
                                        ├─ 失败 → 回 [S5]，评分按钮恢复可点（见 §6.1）
                                        └─ 成功 → 队列下一条 → [S4]（或队列空 → [S7]）
任意状态：系统返回键 → 退出到首页（不弹确认，见下）；401 → 清 token 跳登录。
```

### 各状态 UI 元素与文案（中文）

| 状态 | UI 元素 | 文案 |
|---|---|---|
| S0 未登录 | 居中图标文字 + 主按钮「去登录」+ 灰字说明 | 标题「背单词」/「登录后同步你的复习进度」/ 按钮「去登录」 |
| S1 加载 | 顶部进度区 + 卡片位置一个灰色占位块（无转圈） | 「正在获取今日队列…」 |
| S1E 加载失败 | 居中错误文案 + 描边按钮「重试」（重新 GET today） | 「网络不可用，请检查连接后重试」 |
| S4 正面 | 顶栏(返回+进度条+计数)、卡片(单词大字+音标)、底部灰字提示 | 提示「点击卡片查看释义」 |
| S5 背面 | 同顶栏 + 翻转后的卡片(释义区) + 底部 4 档评分栏 | — |
| S6 提交中 | 4 个评分按钮全部禁用（防双击），其余不变 | 按钮文字不变，无需 loading 文案（<1s 正常） |
| S6F 提交失败 | 顶部内嵌 toast 条（红色细条，2.5s 自动消失） | 「评分未保存，请再按一次」 |
| S7 结算 | 居中大字 + 一句副文案 + 本轮统计小字 + 描边按钮「返回首页」 | 大字「今日已清空」/ 副文案「复习完成，剩下的交给时间。」/ 统计「本轮 20 张 · 忘记 3 · 轻松 8」 |

### 边界决策

- **中途退出不弹确认**：评分是逐卡同步提交的（成功才算完成，符合 §3.2），退出时所有已按的评分已持久化，未评分的卡明天仍在队列里。数据模型天然安全，加确认弹窗是负收益，省掉。
- **返回键**：背词页是独立页（无汉堡菜单，仅左上返回箭头 + 系统返回键等效），返回 = 回首页。
- **队列空**：进入时 dueToday=0 直接落在 S7 结算页（不用单独空态页，文案即空态）。
- **401**：任何背词请求返回 401 → 清 token、双写存储清空 → 跳登录页；登录成功后需手动重进背词（不做自动续接，省一个栈管理）。
- **lookup 预取（关键实现细节）**：lookup 有 IP 限流 30/min。**必须串行预取**：进页面后先取第 1、2 张的释义（间隔 ≥300ms），之后每翻一张卡补取队列中第 +2 张。结果写入与查词共用的 localStorage 缓存（key=`lk:<word>`，同最近 200 条缓存）。预取失败不重试，翻面时兜底再拉（见 §6.4）。

## 2. 卡片正面 / 背面布局

翻面用纯 CSS 3D flip（约 8 行：`.card.flipped` 切换 `transform: rotateY(180deg)`，正反面 `backface-visibility: hidden`）。嫌麻烦可退化为瞬时切换，无功能损失。

**正面（自测面）**——只放单词 + 音标：
```
┌──────────────────────────┐
│                          │
│        abandon           │   34px，#111，加粗，居中
│      /əˈbændən/          │   15px，#999，居中（无音标则整行不渲染）
│                          │
│    点击卡片查看释义        │   13px，#bbb，固定在卡内底部
└──────────────────────────┘
```
不放 retrievability / elapsedDays：「上次复习 3 天前」是记忆线索但也可能变成提示，v1 一律不放，少一个元素少一个判断分支。

**背面（释义面）**：
```
┌──────────────────────────┐
│  abandon  /əˈbændən/     │   复用正面头部（18px，略小）
│  ─────────────────────   │
│  v. 放弃；抛弃            │   首词义：17px，#111，加粗
│  n. 放纵，放任            │   其后词义：15px，#333，常规
│  ─────────────────────   │
│  例句                     │   12px，#999，区块标题
│  He abandoned his car…   │   14px，#333
│  他丢弃了他的车。          │   12px，#999
│  ─────────────────────   │
│  词形变化 ▾               │   <details><summary>，13px，#666
│  ┌过去式 abandoned┐…     │   展开后 chip 横排，13px，#556 边框 #e5e5e5
└──────────────────────────┘
```
- 释义按 `groups` 词性分组：每组一行 `.lr-pos`（灰 chip，如 `v.`）+ meanings 用「；」串成一行。**fallback**：`groups` 为空时拆 `translation`（按 `；`/`;`/`\n` 分隔）。
- 例句取 `examples` 前 2 条（index 0、1），有 `zh` 才渲染中文行。
- 「更多信息」用原生 `<details>`，零 JS。首屏折叠。
- 背面内容在正面时就渲染在翻转面后面（DOM 同时存在），翻面零延迟。

### 字段来源对照（全部来自 `GET /api/lookup?word=` 响应）

| UI 元素 | lookup key | 渲染规则 |
|---|---|---|
| 单词 | `word` | 正面/背面头部 |
| 音标 | `phonetic` | 空字符串则不渲染该行 |
| 主要释义 | `groups[].pos` + `groups[].meanings[]` | 第 0 组第 0 条加粗；组内 meanings 以「；」连接 |
| 释义兜底 | `translation` | 仅当 groups 为空 |
| 例句 | `examples[0..1].en` / `.zh` | 最多 2 条 |
| 词形变化 | `exchange` | 键→中文标签映射：p=过去式、d=过去分词、i=现在分词、3=第三人称单数、s=复数、r=比较级、t=最高级、0=原形；无映射的键显示原始键。仅显示有值的项 |
| 不使用 | `definition`/`detail`/`freq`/`tag`/`audio` | v1 不渲染（英英释义与长文留 v2） |

## 3. 四档评分按钮

**结论：下一步预览（「3 天后见」）v1 不显示。**

理由（按项目宪法：契约不改、单人一晚、WebView 无框架）：
1. **数据拿不到**：FSRS 记忆状态（stability/difficulty）在服务端 cardJson 里，`GET /review/today` 只回 `retrievability/elapsedDays`；`POST /api/review` 契约未承诺返回间隔。客户端要准确显示预览只能本地复刻 FSRS 算法——一晚做不完且必然与服务端调度结果不一致，**显示错误的预览比不显示更糟**。
2. 需求 §3.3 只要求「四档评分」，预览属于 Nice-to-have。
3. **留了后门**：代码里判断 `if (resp.next && resp.next[rating])` 才渲染——将来服务端若在 POST 响应中附带 `next` 字段，前端零改动自动出现。

### 按钮规格

| rating | 文案 | 文字/边框色 | 底色 |
|---|---|---|---|
| 1 | 忘记 | #D93025（红） | 白 |
| 2 | 困难 | #E8710A（橙） | 白 |
| 3 | 良好 | #188038（绿） | **#E6F4EA（浅绿实底，视觉主推）** |
| 4 | 轻松 | #1A73E8（蓝） | 白 |

- 布局：固定在视口底部（safe-area 兼容），4 等分一行，高 48px，圆角 8px，1px 描边，间距 8px。仅「良好」加浅色实底做默认引导（Anki 同款逻辑，FSRS 主流评分就是 3），不做动画。
- 按下反馈：仅 `:active` 背景加深，无过渡动画。
- 提交中 4 个按钮 `disabled`，防双击重复 POST。

## 4. 查词结果排版规范（首页直接展示）

层级：单词(黑粗 28px) > 首词义(黑粗 17px) > 正文释义/例句英文(14-15px #333) > 音标/中文/辅助(12-13px #999)。白底，无卡片阴影，区块间用 1px #f0f0f0 分隔线或 24px 间距。

**HTML 结构草案（类名可直接用）**：

```html
<div class="lr">
  <div class="lr-head">
    <h1 class="lr-word">abandon</h1>          <!-- 28px #111 700 -->
    <span class="lr-phonetic">/əˈbændən/</span> <!-- 15px #999，空则不渲染 -->
  </div>

  <div class="lr-groups">
    <div class="lr-group">
      <span class="lr-pos">v.</span>            <!-- 12px #999，白底灰边 chip -->
      <p class="lr-meaning lr-primary">放弃；抛弃</p>  <!-- 首组首条 17px #111 700 -->
    </div>
    <div class="lr-group">
      <span class="lr-pos">n.</span>
      <p class="lr-meaning">放纵，放任</p>        <!-- 15px #333 -->
    </div>
  </div>

  <div class="lr-examples">
    <p class="lr-sec-title">例句</p>
    <div class="lr-example">
      <p class="lr-ex-en">He abandoned his car in the snow.</p>
      <p class="lr-ex-zh">他把车丢在了雪地里。</p>
    </div>  <!-- 最多 2 条；en 14px #333 / zh 12px #999 -->
  </div>

  <details class="lr-more">                      <!-- 原生折叠，零 JS -->
    <summary>词形变化</summary>                   <!-- 13px #666 -->
    <div class="lr-exch">
      <span class="lr-exch-item">过去式 abandoned</span>
      <span class="lr-exch-item">过去分词 abandoned</span>
    </div>
  </details>
</div>

<div class="toast">已加入单词本</div>  <!-- 底部居中浮出，2s 消失 -->
```

**加入单词本：不用按钮，用自动加入 + 轻反馈**（需求 §3.1 明确自动加入，与网页版一致）：
- 查词成功（英文词且 groups/translation 非空）→ 自动走 §3.2 的变更队列（本地权威副本 + 待同步队列）→ 底部 toast「已加入单词本」，2s 消失。
- 重复查同词：本地副本去重，toast 显示「已在单词本中」或直接不弹（推荐后者，少打扰）。
- 同一套 `.lr` 结构在背词卡背面复用（类名即本文 §2 的渲染规则），写一次渲染函数两处调用。

## 5. 进度与激励

- **背词页顶栏**：`←` 返回 + 细进度条（高 3px，#111 填充于 #eee 轨道，`width:%` 即可，加 0.2s width 过渡——这是状态反馈不是装饰）+ 右侧计数「12/20」（13px #666）。进度 = 已成功提交的评分数 / total。
- **结算页**（也是空队列态）：
  - 大字：「今日已清空」（22px #111 700，居中）
  - 副文案一句话：「**复习完成，剩下的交给时间。**」（14px #999）——扣记忆曲线主题、陈述式、不喊口号；备选「明天再来」。
  - 统计小字：「本轮 20 张 · 忘记 3 · 轻松 8」（本地计数，零成本）。
  - 按钮：「返回首页」（描边，非实心——结算不是成就页）。
- **不做的**：连续打卡、彩带/撒花动画、弹窗评级引导。白底极简原则下，激励只靠「清零的进度条」本身。

## 6. 边界清单（逐项实现口径）

1. **评分请求失败**：POST 超时 8s 或非 2xx → 当前卡保持在背面、toast「评分未保存，请再按一次」、按钮恢复可点；用户再按任一评分 = 用该评分重发。**不做后台静默补发队列**——需求要求不静默丢失，显式重试即可满足且实现最简。按钮 disabled 从点击到响应，杜绝双击双 POST。
2. **复习中查词**：v1 不做卡内跳转查词（翻面后释义已在卡上，跳转入口与翻面手势冲突）。用户中途退出回首页查词无任何副作用：已评分已提交、未评分仍在服务端队列。
3. **队列单词不在词典（lookup 404）**：不阻塞流程。背面正常翻面，释义区降级为一行灰字「词典未收录，仅可评分」，评分按钮照常可用（用户认识就评 3/4）。正面不受影响。
4. **lookup 网络失败**：背面释义区先显示「释义加载中…」，6s 超时或失败 → 显示「释义加载失败」+ 内联小按钮「重试」；评分不依赖 lookup，随时可评。下次遇到同词走缓存。
5. **lookup 限流（30/min）**：§1 预取策略（串行 + ≥300ms 间隔 + 只预取 +2）保证 20 张卡最多 ~22 次/min，安全。预取请求遇 429 直接放弃（有翻面兜底）。
6. **加载队列失败/5xx**：S1E 错误态 + 重试；连续 3 次失败文案不变，靠用户手动重试（不做自动重连，省状态）。
7. **401**：见 §1。清双写 token → 跳登录。
8. **弱网下进入**：today 请求超时 10s，期间占位文案不转圈；所有网络态页面均有文字说明，杜绝白屏（§3.5）。
