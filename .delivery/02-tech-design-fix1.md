**为什么不照 P-9 的建议折进 T-06 微轮，而是新开 T-25（需要 TPM 追认的点）**：
1. **文件不相交硬判据**：T-06 的微轮（A-32-1(b) 启动 fail-fast + A-32-6 事务内 RMW）**此刻正在写 `db/**`**。R-41 若并进批次3 的 T-06，同批次内两个任务会同时声明 `db/**` 写权，直接违反 §10 的"同批次可写集合两两不相交"。
2. **范围性质不同**：T-06 的边界是"DDL 单一源 + 迁移框架"，R-41 跨 **DDL → 驱动读路径 → service/属主过滤 → tRPC 两个 router → Web 一条分支 → 集成用例**六层，塞进任何既有任务都会破坏那一条"精确文件清单可机检"的性质。

**本期做与不做的边界（写进了 F-5 与 M7 说明，供 PM/QA 引用）**：`UNIQUE (word,qtype)` 是表级约束（SQLite 只能重建表才能删；PG `DROP CONSTRAINT` 落在迁移白名单外且会让两驱动 schema 永久分叉），**所以本期做不到"每用户一行"**；隔离按 **R-41③ 的 (b) 读路径属主过滤**实现，代价 = 同一词两人互挤一行 → 缓存命中率下降（RK-14）。R-41③(a) 的"公共题池"不采用，因为它要求"永不用于评分回写"，在同一行上做不到。真隔离 = 下一期四步迁移（建新表 → 双写 → 切读 → 删旧）。
