### 2.4 三条最容易被验收抓住的判据 —— 逐条给出覆盖证据

**A. R-12④「随机自测不改任何卡 `due`」→ `S-09`（study:594-617）**
证据链（4 层，全在一条用例内）：
1. 预置 review 档队列快照 `reviewSnapshot` 塞进查询缓存，取引用 `before`（study:596-599）。
2. 自测档整轮评满 3 张（`for rating of [1,2,3]`，study:604）。
3. **写侧 0 请求**：`postCount('/api/review') === 0`、`postCount('/api/review/undo') === 0`、`api.written` 深度等于 `[]`（study:607-609）⇒ 本轮不存在任何能改动 `data/due` 的入口。
4. **读侧不被改写也不被重取**：`getQueryData(reviewKeys.queue('review'))` 与 `before` **引用相等** 且 `toEqual(reviewSnapshot)`（study:612-613）⇒ 复习档那份 `due` 序列不可能被这一轮动过。
5. 收尾还断言自测走完照样落完成页（`#/study/done?mode=selfTest&cards=3`）且撤销入口为 `null`（study:614-615）⇒ "不改 due" 不是靠"没走完"来作弊的。
> 唯一 DB 级快照断言（PRD 括号里的"数据库快照断言"）属后端 T-15，见缺口 G-2。

**B. R-13②「走完最后一张不产生新评分记录、不许归 0 回第一张」→ `S-19`（study:910-926）+ `C-04b`（completion:424-440）**
1. `S-19`：评满 3 张后 `postCount('/api/review') === 3`，地址切走（study:917-920）；再等 8 帧后 **`postCount` 仍为 3、undo 恒 0**（study:924-925）⇒ 落页之后不产生新评分记录。
2. `S-19`：`container.textContent` **不含** `第 1 张，共 3 张`（study:921）⇒ 指针没有归 0 回第一张。
3. `S-20`（study:927）：`completionHref ↔ parseSummaryQuery` 往返一致，异常数字收敛为 0 且地址里不出现 `NaN`/`Infinity` ⇒ 完成页数字只从地址读，不经任何"重新起一轮"的状态。
4. `C-04b`（completion:425）：在**完成页上**点遍打卡区与两颗按钮，`POST /api/review` **恒为 0**，地址仍停在 `#/study/done` ⇒ 完成页自身也没有隐式再评分路径。
